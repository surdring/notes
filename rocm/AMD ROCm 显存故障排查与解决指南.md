这份指南基于刚才我们共同排查 **AMD ROCm 环境下大模型显存不足及进程无法终止** 的全过程整理而成。

当你在显存理论上足够的情况下遇到 `Out of Memory`，且无法清理显存时，请参考此流程。

---

# AMD ROCm 显存故障排查与解决指南

## 1. 故障现象
*   **报错信息**：加载模型时提示 `cudaMalloc failed: out of memory` 或 `unable to allocate ROCm buffer`。
*   **矛盾点**：模型权重大小（如 18GB）远小于显卡总显存（如 32GB），理论上应该能运行。
*   **异常行为**：尝试终止占用显存的进程无效，进程“杀不死”。

## 2. 排查步骤

### 第一步：检查显存实际占用
不要只看程序报错，要看硬件状态。
```bash
rocm-smi
```
*   **关注点**：查看 `VRAM%`。
*   **判断**：如果当前没有运行任务，但 `VRAM%` 很高（如 >10%），说明有残留进程占用了显存。

### 第二步：查找并尝试终止残留进程
找出占用显存的进程 PID。
```bash
rocm-smi --showpids
# 或者
sudo lsof /dev/kfd
```
尝试强制终止（通常第一步操作）：
```bash
kill -9 <PID>
```
*   **判断**：重新运行 `rocm-smi`。如果进程消失且显存清空，问题解决。如果进程**依然存在且 PID 不变**，进入第三步。

### 第三步：诊断进程状态（关键）
查看进程的详细状态，确认为何杀不死。
```bash
# 将 <PID> 替换为你的进程号
ps -up <PID>
```
查看输出中的 **`STAT`** 列：
*   **`R` / `S`**：正常运行或睡眠，通常能被 `kill` 掉。
*   **`Z` (Zombie)**：僵尸进程。进程已死，显存通常已释放，只剩空壳。
*   **`D` / `Ds` (Uninterruptible Sleep)**：**不可中断睡眠**。这是最严重的情况。

### 第四步：结论分析
如果状态是 **`Ds`**：
*   **含义**：进程正在等待硬件（GPU）响应，但硬件已无响应（死锁）。
*   **后果**：操作系统内核会屏蔽所有信号（包括 `kill -9`），直到硬件恢复。
*   **根本原因**：AMD 显卡驱动崩溃或 GPU 硬件死锁。

## 3. 解决方案

### 紧急处理（唯一解）
面对 `Ds` 状态进程，软件层面的命令已失效。
1.  **重启系统**：
    ```bash
    sudo reboot
    ```
2.  **强制断电**：如果 `sudo reboot` 也卡住（因为系统关机时也在等进程结束），请长按电源键强制关机。

---

## 4. 预防措施（防止再次崩溃）

重启后，为了避免再次把显卡驱动“搞崩”，运行大模型（特别是 32B+）时请务必配置以下参数：

### A. 限制上下文窗口 (Context Window)
Qwen 等模型的默认上下文极长（32k+），加载时会预分配巨量显存导致溢出或驱动崩溃。
*   **参数**：`-c`
*   **建议**：
    ```bash
    ./llama-server ... -c 8192  # 限制为 8k，显存紧张时改为 4096
    ```

### B. 避免显存满载 (Offload Layers)
不要试图填满 100% 的显存。ROCm 需要连续内存块，且系统显示界面也需要显存。
*   **参数**：`-ngl` (Number of GPU Layers)
*   **建议**：不要加载所有层，保留 10-20% 的缓冲空间。
    ```bash
    # 假设模型共 64 层，只加载 50 层到 GPU
    ./llama-server ... -ngl 50
    ```

### C. 禁用内存映射 (可选)
如果频繁遇到分配失败，尝试禁用 mmap，强制通过 read 加载数据。
*   **参数**：`--no-mmap`

---

## 总结命令示例

下次启动 Qwen3-VL-32B 时的安全命令：

```bash
./llama-server \
  -m /path/to/model.gguf \
  -c 8192 \        # 1. 限制上下文，防止OOM
  -ngl 50 \        # 2. 不全层加载，给系统和驱动留余地
  --no-mmap        # 3. 尝试改变内存加载方式（可选）
```
