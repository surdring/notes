# WeKnora 本机快速开发模式安装步骤（方案A：Docker Postgres 改端口）

本文档基于 `docs/开发指南.md` 整理，面向“本机运行后端/前端 + Docker 启动基础设施”的**快速开发模式**。

适用场景：
- 你本机已经安装并运行了 PostgreSQL（占用默认 `5432`），但仍希望使用 WeKnora 提供的 dev 基础设施（Docker Postgres）
- 你本地模型使用 **llama.cpp**（建议用 `llama-server` 的 OpenAI 兼容接口接入）

---

## 1. 前置条件

- Docker（服务能正常运行）
- Docker Compose（支持 `docker compose` 或 `docker-compose`）
- Go（用于本地运行后端 `make dev-app`）
- Node.js + npm（用于本地运行前端 `make dev-frontend`）

可选：
- Air（后端热重载）：
  - `go install github.com/air-verse/air@latest`

---

## 2. 拉取代码

```bash
git clone https://github.com/Tencent/WeKnora.git
cd WeKnora
```

---

## 3. 配置 .env（关键：DB 端口改为 5433）

在项目根目录创建 `.env`：

```bash
cp .env.example .env
```

然后编辑 `.env`，**增加或修改**以下项：

- `DB_PORT=5433`

说明：`.env.example` 默认未提供 `DB_PORT`，需要你在 `.env` 中手动新增该行。

说明：
- 快速开发模式会使用 `docker-compose.dev.yml` 启动一个 Docker Postgres，并做端口映射：`${DB_PORT:-5432}:5432`
- 你本机 Postgres 如果占用 `5432`，Docker Postgres 就会启动失败，因此这里改成 `5433`（或任何空闲端口）

建议保持（初次跑通优先）：
- `DB_DRIVER=postgres`
- `RETRIEVE_DRIVER=postgres`
- `STORAGE_TYPE=local`
- `STREAM_MANAGER_TYPE=redis`

---

## 4. 启动开发基础设施（Docker）

### 4.1 启动最小集（推荐先跑通）

```bash
make dev-start
```

等价命令：

```bash
./scripts/dev.sh start
```

默认会启动：
- PostgreSQL（宿主机端口：`localhost:5433`，容器端口：5432）
- Redis（`localhost:6379`）
- DocReader（`localhost:50051`）

### 4.2 可选：按需增加组件

如果你需要对象存储/多模态图片等能力，建议额外启动 MinIO：

```bash
./scripts/dev.sh start --minio
```

其它可选项：
- `--qdrant`：Qdrant 向量库
- `--neo4j`：Neo4j 图数据库
- `--jaeger`：Jaeger 链路追踪
- `--full`：全部启用

---

## 5. 本地启动后端（Go）

新开一个终端，在项目根目录执行：

```bash
make dev-app
```

等价命令：

```bash
./scripts/dev.sh app
```

说明：
- 脚本会自动读取 `.env` 并导出环境变量
- 同时会把容器内的地址覆盖成 `localhost`（例如 `DB_HOST=localhost`、`DOCREADER_ADDR=localhost:50051`）
- **端口会沿用 `.env` 的 `DB_PORT`**，因此只要你按第 3 步设置了 `DB_PORT=5433`，后端就会连接到 `localhost:5433`

后端默认监听：
- API：`http://localhost:8080`
- 健康检查：`http://localhost:8080/health`

---

## 6. 本地启动前端（Vite）

再开一个终端：

```bash
make dev-frontend
```

等价命令：

```bash
./scripts/dev.sh frontend
```

前端开发服务器：
- `http://localhost:5173`

---

## 7. llama.cpp（llama-server）接入建议

### 7.1 确认 llama.cpp 以 OpenAI 兼容方式启动

建议使用 `llama-server`（示例，端口按你实际情况调整）：

```bash
./llama-server -m /path/to/model.gguf --host 0.0.0.0 --port 8000
```

可用以下方式自检（示例）：

```bash
curl http://127.0.0.1:8000/v1/models
```

注意：
- 在快速开发模式中，WeKnora 后端运行在宿主机，因此模型地址通常应填写 `http://127.0.0.1:8000/v1`（而不是 `host.docker.internal`）

### 7.2 在 WeKnora Web UI 中配置模型（推荐）

1. 打开前端：`http://localhost:5173`
2. 注册/登录
3. 在“模型配置/知识库设置”页面配置：
   - LLM（对话/Agent）：
     - Base URL：`http://127.0.0.1:8000/v1`
     - API Key：若 llama.cpp 未启用鉴权可留空
     - Model：填写 `GET /v1/models` 返回的模型 ID

Embedding（非常关键）：
- 导入文档并建立索引依赖 Embedding
- 如果你的 llama.cpp 不支持 `/v1/embeddings` 或效果不佳，建议单独部署 embedding 服务（常见做法：LLM 用 llama.cpp，Embedding 用专用 embedding 模型服务）

---

## 8. 验证流程（最小闭环）

1. 基础设施容器已启动：
   - `make dev-status` 或 `./scripts/dev.sh status`
2. 后端可用：
   - `http://localhost:8080/health`
3. 前端可用：
   - `http://localhost:5173`
4. 在 UI 中配置模型后：
   - 创建知识库
   - 上传一个小文档（txt/pdf）
   - 等待解析/向量化完成
   - 发起一次问答验证链路

---

## 9. 常见问题

### 9.1 `make dev-start` 报端口占用

现象通常类似：`bind: address already in use`。

处理：
- 确保 `.env` 里设置 `DB_PORT=5433`（或换一个未占用端口）
- 然后重新执行：`make dev-start`

### 9.2 上传文档失败/一直处理中

优先排查：
- 模型是否配置完整（尤其 Embedding）
- 查看日志：
  - 基础设施：`./scripts/dev.sh logs`
  - 后端：查看运行 `make dev-app` 的终端输出

---

## 10. 停止开发环境

```bash
make dev-stop
```

等价命令：

```bash
./scripts/dev.sh stop
```
