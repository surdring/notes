# 第一章 概述

## 1.1 产品概述

会计平台就是为各业务系统,如应收应付、费用管理、供应链、资产管理等提供一个与财务系统接口,实现财务业务数据一体化的平台。

通过会计平台可以将各业务单据自动转换成总账凭证、责任凭证,将总账凭证转换为责任凭证或者成本单据等,从而实现财务与业务系统数据的无缝连接,保证业务数据与财务数据的一致性,同时,也能够大幅度减少财务人员的人工工作量,避免业务数据与财务数据的人为误差。

### 1.2.3 说明

会计平台分两层架构体系

一层为管理员配置级别，主要为管理员提供配置平台通用规则或基础数据信息的功能，如设置影响因素信息、转换模板的单据属性以及在通用平台设置中需要用到的单据项目信息。

另一层为业务员设置级别，这些功能主要是给各业务系统的业务员提供，通过这里的功能配置，就能获得业务员需要的由业务单据转换生成的各种凭证或单据信息。

#### 会计平台主要完成:

1. 将各业务系统中的单据转换生成相应组织相应财务账簿中的总账凭证。
2. 将各业务系统中的单据转换生成相应组织相应财务账簿中的责任凭证。
3. 通过总账凭证拉式生成责任凭证。
4. 通过总账凭证拉式生成成本管理单据。
5. 通过责任凭证拉式生成成本管理单据。
6. 通过成本管理单据推式生成总账凭证或责任凭证。
7. 通过递延所得税单据将递延所得税的计算结算生成凭证到与税务账簿相对应的总账账簿。

## 3.9 科目对照表

### 3.9.1 概述

NC 系统中，从多的基本档案间，不同档案类型下的档案存在不同的对应关系和转换关系。这种转换关系是一个或几个档案的组合生成另外一个档案值的功能，具体来说，就是会计平台分类定义下的对照表，用于明确其他档案组合转换成会计科目或要素的关系。

NC 系统作为一个集成了各个业务系统的复杂体，各档案间的固定关系会被多个业务系统所使用，如果每个业务系统都定义自己的这种关系，不仅加大实施的工作量，而且对于后期的维护也很麻烦。因此，需要把这种关系的定义包装起来，达到一次定义，多次被使用的效果。科目对照表即是用于此目的。

科目对照表用于针对业务系统的各种影响因素设置过滤条件，提取出对照表作为公用设置，使业务系统中的单据按对照表的规则生成凭证或其他信息。科目对照表分为集团、业务单元两层设置，集团定义参照集团级档案，业务单元定义则参照当前组织级档案。

# 3.10 要素对照表

## 3.10.1 概述

NC 系统中,从多的基本档案间,不同档案类型下的档案存在不同的对应关系和转换关系。这种转换关系是一个或几个档案的组合生成另外一个档案值的功能,具体来说,就是会计平台分类定义下的对照表,用于明确其他档案组合转换成会计科目或要素的关系。

NC 系统作为一个集成了各个业务系统的复杂体,各档案间的固定关系会较多个业务系统所使用,如果每个业务系统都定义自己的这种关系,不仅加大实施的工作量,而且对于后期的维护也很麻烦。因此,需要把这种关系的定义包装起来,达到一次定义,多次被使用的效果。要素对照表即是用于此目的。

要素对照表用于针对业务系统的各种影响因素设置过滤条件,提取出对照表作为公用设置,使业务系统中的单据按照报表的规则生成凭证或其他信息。要素对照表分为集团、业务单元两层设置,集团定义参照集团级档案,业务单元定义则参照当前组织级档案。

NCV6.3 版支持要素的对照表可以被项目预算所使用(《NCV6.3》之前的同一对照关系,如果生成责任凭证/项目成本单据以及项目预算控制存货或报销时,需要在会计平台和项目预算两个地方设置,维护工作量大,而且容易出错),同一对照表既可以被会计平台的分类定义引用,也可以被项目预算要要素生成执行数来使用。

V6.5 中【责任会计管控范围】的名称修改为【账簿类型】,其参照为系统的账簿类型档案。

b) `getaccountbook(财务组织,账簿类型)`: 根据财务组织和账簿类型取财务核算账簿。如果财务组织没有启用指定账簿类型的核算账簿，则返回空值。

c) `getdefaultaccountbook(业务单元)`: 取该业务单元所属的主体财务核算账簿。即当该业务单元是财务组织并已建财务核算账簿，则返回该组织对应的主体账簿，否则返回业务单元所属公司的主体账簿。

g) `getexchangerate(来源币种主键,目的币种主键,日期)`: 汇率获取函数，根据来源币种、目的币种和日期取汇率。

## 附录1：名词解释

* **影响因素**: 指各业务模块在入账设置和分类定义中引用之后, 会计平台判断生成哪个主体及哪个会计账簿的凭证的依据, 系统支持将业务单据上的项目定义为影响因素。
* **入账规则**: 指在会计平台定义的业务单据生成哪个会计主体以及哪个会计账簿的凭证的规则。
* **总账凭证**: 会计平台支持生成财务核算账簿和责任核算账簿的凭证, 记入财务核算账簿的凭证为总账凭证。
* **责任凭证**: 会计平台支持生成财务核算账簿和责任核算账簿的凭证, 记入责任核算账簿的凭证为责任凭证。
* **基础档案**: 指在基础数据中设置的档案, 会计平台通过影响因素定义, 将这些档案设置为影响因素, 作为判断入哪个会计主体哪个会计账簿凭证的依据。
* **实时凭证**: 是指所有原始单据根据业务类型的会计描述实时生成的一张临时凭证, 并非有效的会计凭证, 在总额的所有凭证显示处不可见, 在查账时可选择查看。
* **会计凭证**: 会计凭证是记录经济业务, 明确经济责任的书面证明, 是用于登记账簿的重要依据, 企业发生的各种经济业务, 如现金的收付、物资的进出、往来款项的结算等等, 必须由经办经济业务的有关人员写明经济业务内容, 并在会计凭证上签名盖章, 以示负责。
* **交易类型**: 交易类型是单据类型组的细分, 用于细化对各单据的配置和管理。
* **核算账簿**: 也叫账簿体系或 SDB, 是由具有相同记账本位币、相同会计科目结构、相同会计期间的多个会计主体的财务账的集合。
* **分类定义**: 定义一些科目的集合, 将某些科目归为一类, 它们的影响因素是相同的。
* **对照表**: 当业务系统的单据生成总账凭证或责任凭证时, 需根据单据上的字段内容适配会计科目或核算要素, 这个适配的对应关系通过对照表来设置。
* **拉式生成**: 主动生成由来源方主动触发, 即通过入账规则判断要生成的目的方。
* **取数生成**: 取数生成由目的方触发, 由“取数规则”判断要取数的来源方及取数内容。
