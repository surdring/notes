# RAGFlow：知识库文件列表集成“导出 OCR（jsonl/md/llm_md）”功能日志

- 日期：2026-01-05
- 目标：把“图片/文档解析后的 OCR chunks 导出能力”从脚本集成到 UI（知识库 -> 文件列表行操作），用户无需手工脚本与 API Key，即可一键下载。

## 1. 背景与动机

- 现状：RAGFlow 解析图片（Picture Parser）后，会生成大量 chunks（包含 OCR 拼接文本、表格类结构信息等）。
- 诉求：
  - 在 UI 里直接导出该文档的 OCR chunks；
  - 支持多种格式：
    - `jsonl`：更适合程序消费/二次处理
    - `md`：每个 chunk 独立输出 Markdown（保留 chunk 边界）
    - `llm_md`：将所有表格行合并为一张 Markdown 表，更适合 LLM 读表
  - 权限：应使用 RAGFlow UI 登录态鉴权，不要求用户提供 SDK API Key。

## 2. 设计概览

- 后端新增：登录态下载接口（`/v1`）
  - `GET /v1/document/export_ocr/<doc_id>`
  - 返回 `Content-Disposition: attachment` 触发下载
- 前端新增：知识库文件列表行操作新增“Export OCR”下拉菜单
  - 选择格式后直接下载
- 复用导出逻辑：将原脚本中的导出/表格拼接逻辑抽成后端工具模块，以避免前端拼装与逻辑重复。

## 3. 后端改动

### 3.1 新增共享导出模块

- 文件：`api/utils/ocr_export.py`
- 作用：将 OCR chunks 结构化数据转成三种导出格式（`jsonl/md/llm_md`）
- 核心入口：`build_ocr_export_content(...)`
  - 输入：chunks（含每块文本/表格结构）、导出配置（format/header/sort 等）
  - 输出：导出内容字符串（由 API 负责设置 `Content-Type` 与 `Content-Disposition` 文件名）

### 3.2 新增下载接口

- 文件：`api/apps/document_app.py`
- 路由：`GET /v1/document/export_ocr/<doc_id>`
- 鉴权：登录态（`login_required`）
- 权限校验：校验当前用户对 doc 是否可访问（`DocumentService.accessible(doc_id, current_user.id)`）

#### Query 参数（示例）

- `format`：`jsonl|md|llm_md`（默认 `llm_md`）
- `page_size`：分页拉取 chunks 的 size（默认 200）
- `llm_sort_col`：`llm_md` 模式下按指定列做数字排序（1-based）。
  - 默认值：0
  - 约定：常见“序号”列在第 1 列，因此前端默认对 `llm_md` 传 `llm_sort_col=1`
  - 兼容：当 `llm_sort_col<=0` 且检测到第 1 列多数为数字时，后端会自动按第 1 列排序
- `llm_header`：显式指定表头（可选）
- `llm_header_keywords`：用于自动识别表头行的关键词列表（可选）

#### 返回行为

- `Content-Type`：根据 format 返回
  - `jsonl`：`application/x-ndjson` 或 `application/jsonl`
  - `md/llm_md`：`text/markdown; charset=utf-8`
- `Content-Disposition`：`attachment; filename="..."`

## 4. 前端改动

### 4.1 API 路径新增

- 文件：`web/src/utils/api.ts`
- 新增：`get_document_export_ocr`
  - 指向：`/v1/document/export_ocr/{docId}`

### 4.2 Service 方法新增（Blob 下载）

- 文件：`web/src/services/file-manager-service.ts`
- 新增：`exportOcrFile(docId, params)`
  - `responseType: 'blob'`

### 4.3 下载工具函数

- 文件：`web/src/utils/file-util.ts`
- 新增：`exportOcrDocument(docId, format, opts)`
  - 调用 service 获取 blob
  - 复用 `downloadFileFromBlob` 触发浏览器下载
  - 约定：当 `format=llm_md` 时默认传 `llm_sort_col=1`（按序号列排序）

> 注意：前端修改的是 `web/src/**` 源码，实际被 Nginx 提供的是 `web/dist`。因此改完前端代码后需要重新执行 `npm run build` 生成新的 `web/dist`。

### 4.4 UI：文件列表行操作新增下拉菜单

- 文件：`web/src/pages/dataset/dataset/dataset-action-cell.tsx`
- 行为：在每条文档 action cell 增加“Export OCR”下拉按钮
  - `Export OCR (LLM MD)`
  - `Export OCR (MD)`
  - `Export OCR (JSONL)`
- 禁用条件：文档为 virtual 或处于 running 等不适宜导出状态（与其它按钮一致）。

## 5. Docker 部署下如何验证（不 rebuild 镜像，方式 B）

> 你的线上/当前运行镜像来自 `.env` 中的 `RAGFLOW_IMAGE=.../ragflow:v0.23.1`，默认不会包含本地改动。因此建议先用 bind mount 验证通过后再考虑 rebuild。

### 5.1 新增 debug compose（override）

- 文件：`docker/docker-compose.debug.yml`
- 内容（核心挂载）：
  - 后端：按文件粒度挂载（避免整目录挂载引入版本不一致，导致 worker/task_executor ImportError）
    - `../api/apps/document_app.py:/ragflow/api/apps/document_app.py`
    - `../api/utils/ocr_export.py:/ragflow/api/utils/ocr_export.py`
  - 前端：挂载 `../web:/ragflow/web`
    - Nginx 配置的 `root /ragflow/web/dist;` 不变
    - 说明：只挂载 `web/dist` 容易被 `npm run build` 的“删除并重建 dist 目录”破坏 bind mount（出现旧资源/403/500/按钮不更新等）

### 5.2 本地构建 web/dist

在仓库根目录执行：

```bash
npm --prefix web install
npm --prefix web run build
```

如果宿主机 Node 版本过高（例如 Node 22+），可能遇到 `umi setup` 报 `No such module: http_parser`，可用 Docker 的 Node 20 构建：

```bash
docker run --rm -u "$(id -u)":"$(id -g)" \
  -v "$PWD":/ragflow -w /ragflow/web node:20-bullseye \
  npm install

docker run --rm -u "$(id -u)":"$(id -g)" \
  -v "$PWD":/ragflow -w /ragflow/web node:20-bullseye \
  npm run build
```

### 5.3 启动/重建容器

CPU（示例）：

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yml -f docker/docker-compose.debug.yml --profile cpu up -d --force-recreate ragflow-cpu
```

GPU（示例）：

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yml -f docker/docker-compose.debug.yml --profile gpu up -d --force-recreate ragflow-gpu
```

补充说明：

- 若你已通过 `docker-compose.debug.yml` 挂载了 `../web:/ragflow/web`，通常只要本地重新 build 生成新的 `web/dist`，然后浏览器强刷即可生效，不一定需要重建容器。
- 若后端 Python 也有改动但未生效，或容器内进程未自动 reload，再考虑 `--force-recreate`/重启容器。

## 6. UI 验证清单

- 进入：知识库 -> 文件列表
- 在某个已解析完成的文档行：
  - action cell 能看到 “Export OCR” 下拉按钮
  - 点击三种格式分别触发下载
- 下载内容检查：
  - `jsonl`：每行一个 chunk 记录（可用编辑器/脚本验证换行与字段）
  - `md`：按 chunk 分块输出，保留每块边界
  - `llm_md`：合并为单表（或合并块），表头识别/排序符合预期

## 7. 常见问题与排查

- UI 点了没下载：
  - 看浏览器 Network 是否请求到 `/v1/document/export_ocr/<doc_id>`
  - 检查返回状态码（401/403/500）与返回体
- UI 看不到导出按钮（但代码已改）：
  - 先强制刷新（`Ctrl+Shift+R`），或在 DevTools 勾选 `Disable cache` 后刷新（开发时）
  - 确认容器内实际提供静态资源的目录是 `/ragflow/web/dist`，且该目录内的 `umi.*.js` 确实包含 `Export OCR` 相关字符串
  - 注意：文件列表 action 区域默认是 hover 才显示（样式 `opacity-0 group-hover:opacity-100`），把鼠标移到行上再看
- 导出内容为空：
  - 确认该文档确实已产生 chunks（解析完成）
  - 检查后端分页参数 `page_size`，必要时调小/调大
- 表格行顺序不正确（`llm_md`）：
  - `llm_md` 支持 `llm_sort_col` 按指定列做数字排序（1-based）。常见“序号”在第 1 列。
  - 前端默认对 `llm_md` 传 `llm_sort_col=1`；后端也会在 `llm_sort_col<=0` 时自动识别第一列是否为序号列并排序。
- Docker 下改了代码没生效：
  - 确认是否启用了 `docker-compose.debug.yml` 覆盖
  - 确认 `web/dist` 已重新 build
