# 企微应用回复机器人 — 统一文档

> 本文档整合了部署、配置、运维、故障排查的全部内容。适用于单应用与多应用架构。

---

## 1. 项目概述

本项目是基于企业微信自建应用的机器人服务，采用 FastAPI + Uvicorn 对外提供企微回调接口。

从 v2.0 起，项目采用**多应用架构**：

- 一个服务进程内可以运行多个"企微应用（App）"
- 每个 App 有独立的：
  - 企微凭证（CorpID/Token/AESKey/AgentID/Secret）
  - 回调 URL 路径（`/wecom/<app_id>/callback`）
  - 权限白名单（`allowed_users`）
  - 业务逻辑

当前内置 App：

- **提示词优化助手**（`prompt_optimizer`）
- **物料启用助手**（`material_enabler`）

## 2. 架构设计

### 2.1 核心组件

| 组件 | 文件路径 | 职责 |
|------|---------|------|
| **AppConfig** | `wecom_bot/apps/base.py` | 应用配置数据类，承载 `corp_id`、`token`、`encoding_aes_key`、`agent_id`、`corp_secret`、`allowed_users` 等字段 |
| **WeComApp** | `wecom_bot/apps/base.py` | 应用基类，定义统一接口（`handle_url_verification`、`handle_message`、`process_user_message`） |
| **AppRegistry** | `wecom_bot/apps/registry.py` | 应用注册器，管理所有应用的注册和路由挂载到 FastAPI |
| **AppLoader** | `wecom_bot/apps/loader.py` | 应用加载器，从 `apps_config.json` 加载配置、创建应用实例并调用注册器注册 |

### 2.2 请求处理流程

```text
企微 POST 回调
    ↓
FastAPI 路由（/wecom/{app_id}/callback）
    ↓
AppRegistry 根据 app_id 找到对应 App 实例
    ↓
WeComApp.handle_message()  ← 基类通用实现：验签 + 解密 + XML 解析
    ↓
WeComApp.process_user_message()  ← 子类实现具体业务逻辑
    ↓
通过 WeComClient 发送主动消息回复用户
```

### 2.3 多应用架构优势

1. **独立配置**：每个应用有独立的企微凭证和配置，互不干扰
2. **灵活扩展**：添加新应用只需创建子类并配置，无需修改核心框架代码
3. **统一管理**：所有应用通过一个服务进程统一启动和管理，运维简单
4. **权限隔离**：每个应用可独立配置 `allowed_users` 白名单，精细化控制用户访问
5. **易于维护**：应用之间相互独立，一个应用的异常不会影响其他应用正常运行

## 3. 核心能力与行为说明

### 3.1 提示词优化助手（prompt_optimizer）

- **触发方式**：直接发送任意文本即可（无需 `优化:` 前缀）。
- **处理逻辑**：将文本作为原始提示词调用 LLM 优化，通过企微主动消息返回结果。
- **权限控制**：默认所有用户可用（`allowed_users: []`）。
- **依赖**：需要配置 LLM 服务（支持 OpenAI 兼容接口、本地模型等）。

### 3.2 物料启用助手（material_enabler）

- **触发方式**：发送物料编码列表（英文逗号分隔），例如：`123,456,789`
- **处理逻辑**：
  1. 解析编码列表
  2. 将编码写入 `pre_enable_material` 表
  3. 调用存储过程 `proc_enable_material`
  4. 提交事务
  5. 通过企微主动消息返回执行结果
- **权限控制**：白名单模式（`allowed_users` 非空时仅允许列表内用户）。
- **依赖**：需连接 Oracle 数据库，需安装 Oracle Instant Client。

## 5. 配置说明

### 5.1 apps_config.json（多应用配置）

`apps_config.json` 声明要启动的应用列表，每个应用用 `app_id` 标识。

```json
{
  "apps": [
    {
      "app_name": "提示词优化助手",
      "app_id": "prompt_optimizer",
      "enabled": true,
      "corp_id": "${WECOM_PROMPT_CORP_ID}",
      "token": "${WECOM_PROMPT_TOKEN}",
      "encoding_aes_key": "${WECOM_PROMPT_ENCODING_AES_KEY}",
      "agent_id": "${WECOM_PROMPT_AGENT_ID}",
      "corp_secret": "${WECOM_PROMPT_CORP_SECRET}",
      "allowed_users": [],
      "send_ack_message": true
    },
    {
      "app_name": "物料启用助手",
      "app_id": "material_enabler",
      "enabled": true,
      "corp_id": "${WECOM_MATERIAL_CORP_ID}",
      "token": "${WECOM_MATERIAL_TOKEN}",
      "encoding_aes_key": "${WECOM_MATERIAL_ENCODING_AES_KEY}",
      "agent_id": "${WECOM_MATERIAL_AGENT_ID}",
      "corp_secret": "${WECOM_MATERIAL_CORP_SECRET}",
      "allowed_users": ["ZhengXueEn", "lisi", "wangwu"],
      "send_ack_message": true
    }
  ]
}
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `app_name` | 展示/日志名称 |
| `app_id` | 唯一标识，决定路由前缀 `/wecom/<app_id>` |
| `enabled` | 是否启用 |
| `corp_id/token/encoding_aes_key/agent_id/corp_secret` | 企微应用凭证 |
| `allowed_users` | 白名单：`[]` 所有人可用；非空时仅列表内用户可用 |
| `send_ack_message` | 是否先发送"已收到，处理中..."的被动回复 |

**环境变量替换**：`${ENV_VAR}` 形式会在启动时从 `.env`/系统环境变量中替换。

## 7. 企业微信后台配置（URL 验证/回调）

### 7.1 回调 URL 规则（v2 多应用）

每个应用对应独立回调 URL：

| 应用 | 回调 URL |
|------|---------|
| 提示词优化助手 | `http(s)://<域名或公网地址>/wecom/prompt_optimizer/callback` |
| 物料启用助手 | `http(s)://<域名或公网地址>/wecom/material_enabler/callback` |

### 7.2 URL 验证流程

1. 确保服务已在运行并可被企微访问
2. 在企业微信管理后台 → 应用管理 → 对应应用 → 接收消息 → 设置接收消息服务器配置
3. 填入 URL、Token、EncodingAESKey（必须与 `.env`/`apps_config.json` 一致）
4. 点击保存，企微会立即发起 GET 请求进行 URL 验证
5. 验证成功会返回 `200 OK`，服务端日志显示 `URL 验证成功`

### 7.3 可信 IP（errcode=60020）

当主动发送消息时出现 `errcode=60020 not allow to access from your ip`，需要在企微管理后台将**服务器出口公网 IP** 加入"可信 IP"列表。

## 8. 内网穿透与反向代理

### 8.1 使用 FRP 内网穿透（推荐）

如果你的服务运行在无公网 IP 的电脑上，需要用 FRP 将端口映射到公网。

#### 8.1.1 服务端（公网服务器）frps.toml

```toml
bindPort = 7700
auth.method = "token"
auth.token = "your-token"

# 如果需要 HTTP 域名访问
subdomainHost = "your-domain.com"
```

#### 8.1.2 客户端（本地电脑）frpc.toml

```toml
serverAddr = "47.96.159.100"
serverPort = 7700
loginFailExit = true
auth.method = "token"
auth.token = "your-token"

[[proxies]]
name = "wecombot"
type = "http"
localIP = "127.0.0.1"
localPort = 8001
subdomain = "wecombot"
```

配置后，企微回调 URL 为：`http://wecombot.your-domain.com:7080/wecom/<app_id>/callback`

#### 8.1.3 使用 user systemd 管理 frpc（稳定运行）

创建 `~/.config/systemd/user/frpc.service`：

```ini
[Unit]
Description=frpc
After=network.target
Wants=network.target

[Service]
Type=simple
ExecStart=%h/frp/frpc -c %h/frp/frpc.toml
Restart=always
RestartSec=3
StartLimitIntervalSec=0

[Install]
WantedBy=default.target
```

启动并设置自启：

```bash
systemctl --user daemon-reload
systemctl --user enable --now frpc

# 让用户服务在退出登录后也能运行
sudo loginctl enable-linger $USER
```

#### 8.1.4 稳定运行注意事项

- frpc 必须配置 `Restart=always`，确保断线自动重连
- 启用 `loginctl enable-linger`，确保重启后不登录也能启动
- frpc 断线后企微回调可能中断，恢复方式见"常见问题"章节

### 8.2 使用 Nginx 反向代理（可选）

如果你直接用公网服务器或想用 Nginx 转发：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

#### 8.2.1 配置 HTTPS（推荐）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
sudo certbot renew --dry-run  # 测试自动续期
```

### 9.2 安装 Oracle Instant Client

物料启用功能需要连接 Oracle 数据库。从 [Oracle 官网](https://www.oracle.com/database/technologies/instant-client/linux-x86-64-downloads.html) 下载与数据库版本兼容的 Instant Client。

**版本选择**：
- Oracle 11g 数据库 → 使用 Instant Client 11.2（验证兼容）
- Oracle 19c+ 数据库 → 使用 Instant Client 19+（配合 oracledb 3+）

**安装步骤**：

```bash
sudo mkdir -p /opt/oracle
cd /opt/oracle
# 下载并解压（以 11.2 为例）
sudo unzip instantclient-basic-linux.x64-11.2.0.4.0.zip -d /opt/oracle
sudo unzip instantclient-sqlplus-linux.x64-11.2.0.4.0.zip -d /opt/oracle

# 创建符号链接
cd /opt/oracle/instantclient_11_2
sudo ln -s libclntsh.so.11.1 libclntsh.so
sudo ln -s libocci.so.11.1 libocci.so
```

**配置环境变量**（创建 `/etc/profile.d/oracle.sh`）：

```bash
export ORACLE_HOME=/opt/oracle/instantclient_11_2
export LD_LIBRARY_PATH=$ORACLE_HOME:$LD_LIBRARY_PATH
export PATH=$ORACLE_HOME:$PATH
```

**验证安装**：

```bash
source /etc/profile.d/oracle.sh
sqlplus -v
```

## 10. 常见问题（Troubleshooting）

### 10.1 企微回调无响应（发消息无回复）⭐ 最常见

**现象**：服务在运行、健康检查正常，但给企微应用发消息没有回复。

**根因**：通常是由于 FRP 内网穿透断线/电脑重启，导致企微服务器无法送达回调请求。企微在多次回调失败后可能停止推送 POST 消息。

**快速恢复**：
在企业微信管理后台，将该应用的回调 URL 临时追加版本参数（如 `.../callback?v=20260521`），保存后企微会重新触发 URL 验证：

```log
收到 URL 验证请求 → URL 验证成功（200 OK）
```

验证成功后 POST 推送通常立即恢复。

**长期预防**：
- 确保 frpc 配置了 `Restart=always` 和 `StartLimitIntervalSec=0`
- 启用 `sudo loginctl enable-linger $USER` 让用户服务免登录自启
- 建议将 FRP + wecombot 部署到 24h 在线的小主机/服务器

### 10.2 URL 验证失败

- 确认回调 URL 路径是否正确（多应用必须带 `/wecom/<app_id>/callback`）
- 确认 Token / EncodingAESKey 与企微后台以及 `apps_config.json` 一致
- 确认服务可被企微访问（外网可达），用 `curl http://公网地址/healthz` 测试
- 查看服务端日志：`journalctl -u wecombot -f | grep "URL 验证"`

### 10.3 主动发消息失败（errcode=60020）

在企微管理后台 → 应用管理 → 对应应用 →"企业可信 IP"中，加入服务器出口公网 IP。

### 10.4 Oracle 连接失败

| 错误 | 原因 | 解决方法 |
|------|------|---------|
| `DPI-1050` | Oracle Client 版本过低 | 升级 Instant Client 到 19+，或降级 oracledb 到 2.x |
| `DPY-3010` | thin 模式不支持 Oracle 11g | 配置 `ORACLE_CLIENT_LIB_DIR` 启用 Thick Mode |
| `ORA-12537` / `DPY-4011` | 网络策略路由/VPN 劫持 | `ip route get 192.168.80.90` 检查路由，走内网网卡 |

## 11. 如何添加新应用

### 11.1 在企微后台创建自建应用

获取：CorpID、AgentID、Secret、Token、EncodingAESKey。

### 11.2 创建 App 代码

在 `wecom_bot/apps/` 下新建文件，继承 `WeComApp` 基类：

```python
from wecom_bot.apps.base import WeComApp
from wecom_bot.wecom.crypto import WXBizMsgCrypt
from wecom_bot.wecom.client import WeComClient


class MyApp(WeComApp):
    def __init__(self, config):
        super().__init__(config)
        self.crypto = WXBizMsgCrypt(
            config.token, config.encoding_aes_key, config.corp_id
        )
        self.wecom_client = WeComClient(
            corp_id=config.corp_id,
            corp_secret=config.corp_secret,
            agent_id=config.agent_id,
        )

    async def process_user_message(self, user_id: str, content: str):
        # 业务逻辑
        await self.wecom_client.send_text_message(user_id, "处理完成")
```

> `handle_url_verification` 和 `handle_message` 的通用实现在基类中已提供模板，参考现有 App 复制即可。

### 11.3 在加载器中注册

编辑 `wecom_bot/apps/loader.py`，引入新 App 并在 `load_and_register_apps` 中添加：

```python
from wecom_bot.apps.my_app import MyApp

# 在循环内：
elif app_id == "my_app":
    app_instance = MyApp(app_config)
```

### 11.4 在 apps_config.json 增加配置

```json
{
  "app_name": "我的新应用",
  "app_id": "my_app",
  "enabled": true,
  "corp_id": "${WECOM_MY_APP_CORP_ID}",
  "token": "${WECOM_MY_APP_TOKEN}",
  "encoding_aes_key": "${WECOM_MY_APP_ENCODING_AES_KEY}",
  "agent_id": "${WECOM_MY_APP_AGENT_ID}",
  "corp_secret": "${WECOM_MY_APP_CORP_SECRET}",
  "allowed_users": [],
  "send_ack_message": true
}
```

### 11.5 在 .env 增加环境变量

```bash
WECOM_MY_APP_CORP_ID=...
WECOM_MY_APP_TOKEN=...
WECOM_MY_APP_ENCODING_AES_KEY=...
WECOM_MY_APP_AGENT_ID=...
WECOM_MY_APP_CORP_SECRET=...
```

### 11.6 配置企微回调 URL

回调路径：`http(s)://<域名或公网地址>/wecom/my_app/callback`

### 11.7 重启服务

```bash
sudo systemctl restart wecombot
```

### 11.8 注意事项

1. 每个应用需要在企微管理后台单独创建和配置，获取独立的 CorpID、AgentID、Secret、Token、EncodingAESKey
2. 回调 URL 必须包含正确的 `app_id` 路径：`/wecom/<app_id>/callback`
3. 环境变量建议使用统一的命名规范：`WECOM_<APP_ID>_CORP_ID`、`WECOM_<APP_ID>_TOKEN` 等
4. 禁用某个应用只需在 `apps_config.json` 中将 `enabled` 设为 `false`，无需删除配置

## 12. 从 v1 单应用迁移到 v2 多应用

| 对比项 | v1（旧） | v2（新） |
|--------|---------|---------|
| 回调 URL | `/wecom/callback` | `/wecom/<app_id>/callback` |
| 应用配置 | `.env` 直接配置 | `apps_config.json` + `.env` |
| 环境变量 | `WECOM_CORP_ID` 等 | `WECOM_PROMPT_*` / `WECOM_MATERIAL_*` |

**迁移步骤**：

1. 新建 `apps_config.json`（参考 `apps_config.example.json`）
2. 为每个 App 填写独立企微凭证
3. 将 `.env` 变量改为带前缀的命名
4. 在企微后台为每个应用分别配置回调 URL（注意路径变化）

## 13. 附录：部署脚本（一键安装）

```bash
#!/bin/bash
set -e

echo "=== 企微应用回复机器人部署脚本 ==="
if [ "$EUID" -ne 0 ]; then
    echo "请使用 sudo 运行此脚本"
    exit 1
fi

# 1. 系统更新
echo "步骤 1: 更新系统..."
apt update && apt upgrade -y

# 2. 安装依赖
echo "步骤 2: 安装系统依赖..."
apt install -y python3.11 python3.11-venv python3-pip git curl wget unzip build-essential
apt install -y libaio1t64 || apt install -y libaio1

# libaio 兼容处理
ln -sf /lib/x86_64-linux-gnu/libaio.so.1t64 /lib/x86_64-linux-gnu/libaio.so.1 2>/dev/null || true
ldconfig

# 3. 创建应用用户
echo "步骤 3: 创建应用用户..."
if ! id "wecombot" &>/dev/null; then
    useradd -m -s /bin/bash wecombot
fi

# 4. 提示安装 Oracle Instant Client
echo "步骤 4: 请手动安装 Oracle Instant Client 到 /opt/oracle/"
echo "按回车键继续..."
read

# 5. 部署应用代码（需先上传代码）
sudo -u wecombot bash << 'USEREOF'
cd ~
if [ ! -d "wecom-bot" ]; then
    echo "请先将代码上传到 /home/wecombot/wecom-bot"
    exit 1
fi
cd wecom-bot
python3.11 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
USEREOF

# 6. 配置 systemd 服务
cat > /etc/systemd/system/wecombot.service << 'SERVICEEOF'
[Unit]
Description=WeCom Bot Application
After=network.target

[Service]
Type=simple
User=wecombot
Group=wecombot
WorkingDirectory=/home/wecombot/wecom-bot
Environment="PATH=/home/wecombot/wecom-bot/venv/bin"
Environment="LD_LIBRARY_PATH=/opt/oracle/instantclient_11_2"
ExecStart=/home/wecombot/wecom-bot/venv/bin/uvicorn wecom_bot.main:app --host 0.0.0.0 --port 8001 --log-level info
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
SERVICEEOF

systemctl daemon-reload
systemctl enable wecombot
systemctl start wecombot

sleep 3
systemctl status wecombot --no-pager

echo "=== 部署完成 ==="
echo "请编辑 /home/wecombot/wecom-bot/.env"
echo "然后运行: sudo systemctl restart wecombot"
```
